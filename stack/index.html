HOW WE BUILD

Pinning coding agents to exact dependency versions.

We connect our AI coding agents to GitHits so they read open-source code, documentation, and advisories matching the exact package versions locked in each repository.

PROBLEM

Models confuse library versions.

Coding assistants routinely mix up renamed APIs, unreleased flags, or outdated security advisories. Answers look plausible while failing against the version installed in the repo.

Reading primary source at the lockfile version replaces guesswork with verifiable code. GitHits indexes public open-source code, docs, package metadata, vulnerabilities, and changelogs by exact version over MCP, CLI, and REST.

IMPLEMENTATION

Two integration points.

01 / CODING AGENTS

Version-pinned MCP search

Configured across SyberLabs repositories so coding agents such as Claude Code inspect dependency source, docs, changelogs, and security advisories at exact pinned versions before editing or upgrading.

02 / THIS SITE

Build-time dependency panels

Product pages support build-time snapshots from GitHits’ package API (api.githits.dev/v1) showing licenses, latest versions, and known advisories. Panels render only fetched fields and stay hidden until a live snapshot publishes.

SETUP

Configuration commands.

On a developer machine, one command detects installed coding agents, configures GitHits, and authenticates via browser OAuth (token stored in the OS keychain):

npx githits@latest init

Repositories can also register the server for every agent in .mcp.json; first use prompts for sign-in:

{ "mcpServers": { "githits": { "type": "http", "url": "https://mcp.githits.com" } } }

Headless CI builds read GITHITS_API_TOKEN from repository secrets (never committed). Builds succeed even when the token is absent:

# CI: token from the GitHits settings page, stored as a secret
env:
  GITHITS_API_TOKEN: ${{ secrets.GITHITS_API_TOKEN }}

# confirm the token is picked up
npx githits@latest auth status

Commands reflect GitHits documentation as of 8 October 2026.

DISCLOSURE

What leaves our machines.

  • Build-time panels. Sends only public package names and versions parsed from dependency manifests.
  • Agents over MCP. Sends the agent’s query text. Per GitHits documentation, sign-in grants zero access to private repositories; our repo instructions prohibit sending unpublished code, content, tokens, secrets, or personal data.
  • Retention. Per GitHits’ privacy policy (reviewed 8 October 2026), queries and outputs retain for 90 days, logs for 30 days, and training on inputs is off unless opted in.
