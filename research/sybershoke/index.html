RESEARCH NOTE · SB–0129 SEPTEMBER 2026 · REVISION 2

SYBERSHOKE

Break AI workflows on purpose.
Judge only the log.

Sybershoke injects deterministic failures into agent workflows (killed workers, dropped or duplicate messages, slow or broken model providers), grades the plain-text history against strict invariants, and shrinks failures to their minimal cause. Revision 2 tests our first production codebase: the RISE Worker.

00 / ABSTRACT

What revision 2 adds.

Revision 1 established the Week 0 harness: a coordinator/worker reference simulator with 43 tests, 4 seeded bugs, and 5 invariants. Revision 2 adds a modeled Jev/Kev decision path, an 11-finding adversarial self-audit, and an adapter executing the RISE Worker source against 39 recorded production Jev answers.

Pre-registered tests caught two replayable defects: a keyword misfire forcing “Help me drift off to sleep.” to 300 words per minute (fixed in RISE#306 and #308) and the absence of a provider-failure fallback. One of ten pre-registered predictions was refuted and is reported openly.

THE ABSTRACTION

One seed, one fault plan, one plain-text history, one invariant checker.

01 / FIRST-PRINCIPLES DERIVATION

Three terminal states. Two unacceptable outcomes.

Every submitted task finishes accepted, visibly failed, or neither. Sybershoke hunts two bugs: tasks vanishing into “neither” and tasks accepted more than once.

  1. External grading. The system under test never reports pass or fail; the checker reads only its emitted history.
  2. Deterministic replay. One seed reproduces the exact fault plan and failure across machines.
  3. Failure shrinking. Strip non-essential faults until only the trigger remains.
  4. Isolated and combined campaigns. Run each fault type alone and together so one failure mode cannot mask another.

Scope discipline: no service, no extra dependencies, one definitions crate, one simulator, and one CLI command. Adapters for production systems followed only after simulator and checker agreed.

02 / WEEK 0 HARNESS: METHOD

Five faults, five invariants, one shrinker.

Sections 02 and 03 record the Week 0 harness from Revision 1.

Fault kinds
FaultWhat it models
Kill workerkill -9: process dies mid-task and never returns.
Duplicate messageAt-least-once queue delivery.
Drop messageMessage lost in transit.
Stall workerPause outlasting lease, followed by a late submission.
Corrupt outputMalformed model output for one attempt.

Five invariants checked against the history:

  1. Nothing lost. Every submitted task ends accepted or visibly failed.
  2. Nothing accepted twice. At most one acceptance per task.
  3. No phantoms. Nothing appears that was never submitted.
  4. No contradictions. A task is never both accepted and failed.
  5. No unearned acceptance. Every accepted attempt was delivered to a worker.

Independent RNG streams per fault type keep toggling clean, and at least one worker always stays alive. Runs terminate only when queues drain and all live workers go idle, closing an earlier blind spot for late duplicates.

04 / SECOND TARGET: THE JEV/KEV DECISION PATH

Faulting the wrapper around the model.

Models RISE’s decision wrapper from design specs (8s deadline, ~35s Kev cold start, keyword override, cache, and menu validation) without calling live models. Faults inject errors, slow answers, cold starts, truncated payloads, and off-menu choices.

Invariants for the decision path
IdInvariant
I1On-menu plans only.
I2Single terminal outcome within deadline, preserving user text on error.
I3Cache hits match latest prior model plan (judged by plan content, never labels).
I4Explicit pacing, audio, and visual constraints honored.
I5Provider call cap respected.
I6Task liveness and uniqueness (Week 0 simulator only; omitted here).
I7Optional fallback policy: answer every request with a plan even on provider error.

Execution emits plain-text shoke-history/v1 logs so any external system can run shoke check FILE without linking Rust. All six seeded bugs were caught; the keyword-override bug failed 200 of 200 runs with zero injected faults.

05 / RED TEAM SELF-AUDIT

Eleven findings that corrected our own model.

Adversarial review logged eleven ranked findings, adding 13 regression tests (76 to 89) and surfacing three decisive corrections:

Label-free cache checking (I3).

Judging cache hits by an origin=fallback tag missed unlabeled fallback caching (0 of 200). Switching to pure plan-content comparison caught it on 25 of 200 seeds.

Model vs. RISE Worker drift.

Inspecting RISE Worker source code revealed four differences:

  • Single-call execution with no retries (retry-storm bug has no live counterpart).
  • 8-second timeout covers the provider call only, not total request time.
  • Cache key uses exact intent plus variation cohort, not normalized text.
  • Zero fallback on provider error (readers receive an error, not a plan).

Keyword overrides and menu validation matched the Worker source.

Assumption-sensitive counts.

Changing assumed fault windows shifted counts up to 8x (for example, 49 down to 12 when shortening 1–16s windows to 0.25–2s). Only binary detection (“caught”) and preset-floor I7 elimination survive scrutiny. Narrower shrinker and malformed-history checker bugs were fixed alongside them.

WHAT HELD

All model report counts remained intact, with I3’s 25 catches now derived strictly from plan content with no label.

07 / LIMITATIONS & FOUNDATIONS

Limitations.

Sybershoke combines distributed fault injection [1], history-only invariant checks, and delta-style failure shrinking [2] with no novelty claim or affiliation.

  • One production codebase checked on recorded fixtures, not live traffic. Redis/Neon were in-memory stand-ins and time was virtual.
  • No Kev captures exist yet. RISE has no production Kev deployment; future capture requires a local run.
  • Sound-loudness rankings reflect adapter heuristics rather than native RISE rankings.
  • Model counts reflect assumed parameters; treat only binary catch/miss outcomes as durable.
  • Greedy shrinking yields small plans, not guaranteed minimal ones.
  • Public Jev/Kev workspace is reproducible (scripts/report.sh --check, adapters/rise-worker/check.sh /path/to/RISE); the Week 0 simulator repo remains unpublished.

Establishing general effectiveness over existing test suites still requires comparisons across additional external systems.
