SyberLabs / The Factory

How SyberWork verifies a code change.

AI agents write and repair the code. SyberWork independently executes every check, signs every event into an audit chain, and updates a branch only after human approval.

Six stages of a Build Thread.

Each Build Thread governs one repository change. Every stage logs its output and enforces strict boundaries.

  1. 01

    Start

    Locks the base commit, allowed file paths, and contract version defining checks, policy, and spend limits.

    Never moves a branch or modifies working files.

  2. 02

    Context

    Selects exact code excerpts by file path and symbol match (no embeddings) and logs why each snippet was chosen.

    Never stores raw excerpts; re-reads directly from Git at execution time.

  3. 03

    Propose

    Agents commit edits to isolated refs. By default, SyberWork feeds independent check failures back into a repair loop until checks pass or budget expires (outperforming evolutionary search per dollar on internal fixtures).

    Never edits working files. Agent self-reports are logged as unverified.

  4. 04

    Check

    Executes contract checks on the exact proposed commit inside a fresh worktree with a scrubbed environment, recording exit codes and output hashes. A separate reviewer then inspects the diff; high-severity findings block approval.

    Never substitutes a model’s claim for an executed check.

  5. 05

    Approve

    Evaluates 21 ordered policy rules identically for humans and agents. Requires named human acceptance or role-based secondary sign-off.

    Updates only the thread branch via compare-and-swap. Never pushes, merges, or modifies main.

  6. 06

    Publish

    Pushing branches, opening pull requests, and publishing packages run as separate, idempotent, policy-checked actions.

    Accepting a change never publishes it automatically.

What every Build Thread records.

Independent check outputs
Every pass or fail comes from a process SyberWork executed on exact commit files.
Signed hash chain
Every event hashes into a chain signed by a separate key-holding witness process and written to an append-only log.
Enforced spend caps
Contracts price models, meter spend in real time, halt searches at budget limits, and reject over-budget changes.
Traceable item metrics
Cost, turns, agent duration, repair cycles, lookups, rejections, and human interventions all trace back to source events.

Built with SyberWork.

SyberWork merges its own pull requests through Build Threads, exposing approvers, rule verdicts, and verified check outputs on every PR.

Current boundaries.

  • Isolated worktrees use scrubbed environments, not OS sandboxes; untrusted agent code must execute separately.
  • Approval confirms named checks passed on exact files (tested). It does not guarantee product fit, correctness beyond test coverage, or production deployment.
  • Hash-chain integrity depends on trust in the backing database; it is not yet a public transparency log.
  • Browser verification of documentation runs locally in Attest; no hosted service exists yet.
